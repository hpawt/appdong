# APPDONG

경북대학교 앱동 홈페이지. SvelteKit 2, Svelte 5, PostgreSQL, Drizzle을 사용합니다.

## 로컬 실행

Node.js 22.12 이상을 사용합니다. Windows PowerShell에서는 `npm.cmd`를 사용할 수 있습니다.

```powershell
npm.cmd ci
Copy-Item .env.example .env
docker compose up -d
npm.cmd run db:push
npm.cmd run dev
```

Docker는 로컬 DB 실행에 필요합니다. 기존 PostgreSQL을 쓰면 `.env`의 `DATABASE_URL`을 설정하세요. 로컬 DB는 `DATABASE_SSL=disable`, 운영 DB는 이 변수를 생략하면 SSL 연결을 사용합니다. DB 설정 없이도 공개 정적 페이지와 테스트를 실행할 수 있으며 공지 목록은 서비스 불가 안내를 표시합니다.

공지 업로드에는 Supabase의 공개 `announcements` Storage 버킷과 서버 환경 변수 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`가 필요합니다. 기존 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 설정도 서버에서 호환하지만 새 키는 `VITE_` 이름을 사용하지 마세요. 키는 서버에서만 읽습니다. 업로드는 관리자에게만 허용되며 파일당 10MB, 공지당 첨부파일 20개로 제한합니다. 지원 형식은 PNG/JPEG/GIF/WebP/PDF/TXT/ZIP/DOCX입니다.

## 권한과 계정

현재는 모집 기간이 아니므로 모집 안내 메뉴와 지원서 작성 화면을 숨기고, 직접 제출 요청도 서버에서 차단합니다. 이전 모집 안내·지원서 원본과 SHA-256은 `docs/archive/recruitment-2025-2/`에 보관했습니다. 기존 회원과 제출된 지원서는 유지됩니다.

`src/lib/site-features.js`에서 `recruitment`(가입 지원서 접수)와 `modu`(캘린더·설문)를 켜고 끕니다. 두 기능 모두 현재 `false`입니다. 모집을 재개할 때는 새 모집 안내를 작성하고 일정을 확인하세요. `modu`는 신규 테이블을 준비한 뒤에만 켜세요. 꺼진 캘린더·설문은 공개·관리자 메뉴에 나타나지 않으며 직접 접근도 차단됩니다.

지원서 편집기는 다음 모집을 위해 유지됩니다. 긴 답변 임시 저장은 사용자 동의 시에만 해당 브라우저 탭의 `sessionStorage`를 사용하며 이름·전화번호·학번·비밀번호는 저장하지 않습니다. 저장본은 24시간 후 복원 대상에서 제외되고, 복원은 명시적으로 선택해야 하며 제출 성공 시 삭제됩니다. 작성 중 이탈 경고, 제출 중 표시와 연속 제출 방지를 포함합니다. 현재 공개 경로에서는 편집기가 열리지 않습니다.

메인·로그인·가입 화면은 작은 화면에 맞게 조정했으며 모바일 메뉴는 키보드 포커스를 유지하고 닫힐 때 비활성화됩니다. 페이지별 공유 제목·설명·표준 URL을 제공하고 계정·관리자·모집 종료 페이지에는 검색 제외 정보를 제공합니다. 기존 PNG/JPEG 원본을 보존하고 `static/optimized/`의 WebP 사본을 우선 제공하며, 임원진 이미지는 지연 로딩합니다. 공지 서식 스타일은 공지 본문·편집기에서만 불러옵니다.

- 신규 가입자는 `USER`입니다. 최초 관리자는 DB 관리 도구에서 해당 계정의 `role`을 `ADMIN`으로 설정합니다.
- `/admin`은 서버 훅과 각 서버 작업에서 권한을 검사합니다. 회원, 지원서, 공지를 관리할 수 있습니다.
- 마이페이지는 현재 비밀번호를 확인한 뒤 정보를 수정하며, 비밀번호 변경은 모든 로그인 세션을 종료합니다.
- 공개 비밀번호 재설정은 차단되어 있습니다. 운영진은 본인 확인 후 **회원 관리 → 회원 상세 → 비밀번호 재설정**을 사용합니다.
- 세션은 1시간이며 유효 기간의 절반이 지나면 서버와 쿠키의 만료 시간을 함께 연장합니다.

## 검사와 테스트

```powershell
npm.cmd run check
npm.cmd run lint
npm.cmd run test:unit
npm.cmd run build
npm.cmd run test:e2e
```

`npm.cmd test`는 서버 테스트와 브라우저 테스트를 순서대로 실행합니다. Windows 브라우저 테스트는 설치된 Chrome을 사용합니다. 다른 운영체제에서는 Playwright Chromium을 설치하세요(`npx playwright install chromium`).

서버 테스트는 실제 서버 소스를 실행하고 DB와 세션 의존성만 대체합니다. 브라우저 테스트는 DB와 업로드 자격 증명을 비운 상태에서 빌드한 앱과 별도의 편집기 테스트 서버를 실행합니다. 편집기 테스트 서버는 운영 앱에 포함되지 않습니다. 실 DB 연결·동시 제출·Supabase 업로드는 별도의 연결 환경에서 확인해야 합니다.

## 일정 캘린더와 신청·설문 폼

DB 없이 기능을 확인하려면 로컬 서버의 `/playground`에 접속하세요. 일정 등록·수정·삭제, 월 이동, 제목·장소·내용 검색과 종류 필터, `.ics` 내보내기를 사용할 수 있습니다. 설문은 6가지 질문 유형을 편집하고 미리보기·필수 응답 검증을 직접 실행할 수 있습니다. 실제 동아리 일정이나 설문으로 공개되거나 서버에 제출되지는 않습니다.

작업은 현재 페이지 메모리에만 유지됩니다. 등록한 일정과 적용한 설문 정의는 ‘백업 다운로드’로 JSON 파일을 보관하고 ‘백업 가져오기’로 복원하세요. 작성 중인 미적용 입력과 테스트 응답은 백업에 포함되지 않습니다. 일정은 100개, 설문은 1개를 편집할 수 있으며 백업 가져오기는 2MB까지 허용합니다. 잘못된 파일이나 취소한 가져오기는 기존 작업을 유지합니다. 새로고침·이탈 시 작업 손실을 안내합니다.

캘린더 `.ics`는 필터로 선택된 현재 월의 일정 또는 상세 화면의 개별 일정을 내보냅니다. 날짜만 있는 일정은 마지막 날을 포함하며, 하루 일정의 시각은 한국 시간으로 해석합니다. 여러 날에 걸친 시각 포함 일정은 기간을 보존하는 종일 일정으로 내보내고, 시작 시각을 설명에 기재합니다. 종료 시각은 원래 입력에 없으므로 임의로 정하지 않습니다. 검색·필터·내보내기는 이후 DB 기반 캘린더에서도 동일하게 제공됩니다.

`modu-local.zip`의 캘린더와 폼 기능을 SvelteKit·기존 관리자 로그인·PostgreSQL에 통합했습니다. 원본의 로컬 SQLite 서버와 별도 관리자 계정은 실행하지 않습니다. 기존 가입 지원서는 그대로 유지됩니다.

새 DB에서는 `db:push`로 전체 스키마를 생성합니다. 기존 DB에 기능을 추가할 때는 해당 DB의 `DATABASE_URL`을 설정한 환경에서 아래 명령을 **한 번 실행**하세요. 신규 테이블 3개와 인덱스를 추가하며, 기존 회원·지원서·공지 데이터는 변경하지 않습니다. 배포 전에 DB 운영자가 적용해야 하며 앱 실행 중 자동으로 스키마를 수정하지 않습니다.

```powershell
npm.cmd run db:modu
```

- `/calendar`: 월간·목록 보기, 날짜별 일정, 기간 일정, 장소·시간·종일 표시, 중요 공지 고정. 날짜는 한국 시간 기준입니다.
- `/admin/calendar`: 기존 `ADMIN` 계정으로 일정 등록·수정·삭제.
- `/forms`: 공개된 폼 목록. `/forms/[id]`는 응답 링크이며 공개된 폼은 로그인 없이 응답합니다.
- `/admin/forms`: 질문 편집·순서 변경·삭제·미리보기, 공개·비공개와 접수·마감 전환, 링크 공유.
- 질문 유형은 단답형·장문형·이메일·객관식·체크박스·드롭다운입니다. 폼당 1~50개 질문, 선택형 질문당 2~30개 선택지, 폼 정의와 응답은 각각 UTF-8 32KB까지입니다.
- `/admin/forms/[id]/responses`: 제출 당시 질문과 응답 보존, 50개씩 응답 조회, 개별 삭제, CSV 내려받기. CSV는 UTF-8 BOM과 수식 입력 이스케이프를 포함합니다.
- 폼을 수정하면 버전이 변경됩니다. 이전 화면에서 제출하거나 다른 편집 탭에서 저장하면 새로고침을 안내합니다. 폼 삭제는 관련 응답도 삭제합니다.
- 익명 폼 응답은 중복 제출을 제한하지 않습니다. 이메일 발송·Google 연동·질문 파일 업로드는 원본과 같이 포함하지 않습니다.

`tests/modu-database.test.js`는 개발 전용 PGlite PostgreSQL 엔진에서 실제 마이그레이션과 Drizzle 서버 작업을 실행합니다. 운영 PostgreSQL 연결·배포 검증 및 여러 DB 연결의 동시성 검증은 별도입니다. PGlite는 운영 앱에 사용하지 않습니다.

## 구조

- `src/lib/server/permissions.js`: 로그인·관리자 검사
- `src/lib/server/validation.js`, `passwords.js`: 입력 검증과 비밀번호 처리
- `src/lib/server/auth.js`: 세션 생성·검증·갱신
- `src/lib/server/announcements.js`: 공지 입력 검증과 HTML 정리
- `src/lib/components/AnnouncementForm.svelte`: 공통 공지 작성·수정 편집기
- `tests/`, `e2e/`: 서버 및 브라우저 회귀 테스트

운영 DB에는 로컬 검사를 이유로 `db:push`를 실행하지 마세요. 배포 환경은 기존 adapter-auto 설정을 유지하며, 배포할 플랫폼에서 환경 변수를 설정해야 합니다.
